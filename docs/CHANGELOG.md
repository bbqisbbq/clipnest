## 2.9.5（未发布，2026-11-23）

一句话：**条目终于有标题了——自动从正文的一级标题取，也可以自己起一个。**

- 新：**标题**。正文里第一个 `# 一级标题` 会自动变成条目标题（卡片顶部那一行），
  详情页右栏多了「标题」输入框可以手写覆盖。三种状态说得很清楚：`自动`（正文改了跟着变）、
  `手写`（正文再改也不动）、`空`（正文里没有一级标题，卡片不多那一行）。
  派生规则跟渲染器对齐：`#标签` 不算标题（`#` 后没有空格）、代码块（围栏与缩进）里的 `# xxx` 不算、
  二级及以下不算、收尾井号与行内强调/链接语法会被清掉。
- 修：**卡片会把标题显示两遍**。自动派生的标题来自正文那个 H1，卡片顶部又渲染一次 ——
  所以"标题是自动来的"时把正文里第一个 H1 摘掉再渲染（手写标题不受影响，正文照常显示）。
- 改：`entries` 新增 `title_source` 列（`auto` / `user` / 空），走 `ensureColumn` 迁移；
  对端老版本同步来的条目没有这一列，保存时按"标题是否等于派生值"补判，不会被错锁成手写。
- 补：`entry_title_test.go`（15 条派生用例 + SaveEntry 生命周期 + 老数据兼容 + 采集/片段两条路径）。
- 新：**图片 OCR**。截图里复制来的文字现在**能被搜到**了：图片条目入队后由后台单个 worker 串行
  识别（约 0.5~1.2 秒/张，用 Windows 自带的 `Windows.Media.Ocr`，离线、零依赖、不联网），
  结果显示为卡片上的 `OCR 169 字` 徽章，详情页右栏可以看全文、一键「复制识别文字」。
  几件配套的事：① 识别**不动 `updated_at`**（那是同步指纹与排序的等价物，动了等于"所有图片刚被
  编辑过"）；② OCR 文本并进搜索索引，两个字的关键词走 LIKE 分支也带上 `ocr_text`；
  ③ 识别结果跟着条目同步（几 KB，比图片小三个数量级）；④ 没引擎/没语言包时状态记 `unsupported`，
  界面明说，不假装成功。
- 补：`ocr_test.go`（后处理 11 条用例、写结果不改 updated_at、两字词搜得到、非图片条目标 skipped）
  + `ocr_live_test.go`（`CLIPNEST_OCR_LIVE=1` 时才跑真引擎；实测纯色图 979ms、真截图 482ms/169 字）。
- 新：**卡片右键菜单**（通用组件，不是系统菜单 —— 无边框自绘 UI 里弹 Win32 菜单会露出方角浅底）。
  条目：复制内容 / 识别图里的文字（图片）/ 复制识别文字（识别过之后，右侧带字数）/ 打开详情 /
  置顶 / 加入粘贴列表 / 设为片段 / 归档 / 删除。行为按 Windows 手感来：点外面·Esc·窗口失焦都关，
  贴右边或底边自动翻转，↑↓ 选、Enter 执行，删除永远是最后一项且标红。
  **OCR 从此不用先开详情页** —— 右键就能认。
- 改：菜单条目规则抽成纯函数 `lib/entryMenu.ts`（`entryMenuItems(entry, handlers)`），
  组件只管画与关。这样"哪条内容该有哪些操作"能跑断言，不用点鼠标。
- 补：`scratch/entry-menu-check.mjs`（9 项断言：图片才有 OCR、识别过才显示复制识别文字、
  force 随状态、四个开关文案、删除在最后、分组结构、id 唯一）。

## 2.9.4（2026-11-23）

一句话：**输入框加了「隐私模式」；同步包改全量，自动同步间隔默认放宽到 120 分钟。**

- 新：**隐私模式**（详情编辑器 / 底部「记一条」/ 热键快速输入窗各有一个眼睛开关）。
  打开后**只有光标所在的那个段落保持可读**，其余段落在视觉上融进背景（色调压到贴近
  背景，能看出"这里有几行"但读不出字）。这就是输入时的防窥需求，**纯视觉**：不影响
  保存、不影响已保存的内容、也不改变任何数据。开关状态存在 `Settings.PrivacyInput`
  （机器本地字段，不进同步包 —— 家里没人看、公司有人看，不该互相带过去）。
  实现用 CSS Highlight API 注册文字范围，**不往正文里插节点、不加属性**（Vditor 的
  `getValue()` 走 innerHTML，加标记有被写进 markdown 的风险）。
- 修（隐私模式）：**按回车之后要等打字才生效**。光标落到"还没有字的段落"上时，按文字片段找
  归属是找不到的，于是沿用了上一段 —— 用户看到的是"回车没反应"。现在把这种状态单列成
  `NO_READABLE`：当前段落没字 ⇒ **其余有字的段落全遮**，回车那一下就立刻变淡。

- 改：**包里带全量条目，不再只要"最新 500 条"**（去掉 `syncMaxEntries`）。老做法在库超过
  500 条之后，更老的历史永远不上云 —— 另一台机器上永远找不到那部分内容，而且界面上还写着
  "同步成功"。现在 `Store.AllEntries()` 直接读全量（`ListEntries` 的 500 上限是给界面分页的
  保护，不能拿来组包）。包大小改由三件事兜：记录 deflate 压缩、附件 96 MiB 预算、内容没变
  就不重传的指纹；包超过 24 MiB 会写一行日志提醒（服务器配额与 60 秒请求超时才是真瓶颈）。
- 修：**超预算的附件会永远轮不上**。以前按条目顺序一路扣预算，排在后面的附件每轮都被扣光，
  用户看到的是"有些图片就是同步不过来"。现在没发出去的记在 `meta` 的 `sync.blobDeferred`，
  下一轮优先发；单个附件就超过整个预算时不再假称"下轮继续"，而是在结果行里明说"永远发不出去"。
- 修：**归档条目从来不同步出去**。组包走的是 `ListEntries`，而它的 `where()` 永远带一句
  `archived = 0` —— 于是"归档"只在本机生效，另一台机器上照样能搜到、照样出现在快速粘贴窗。
  真机上就有 3 条这样的条目（12 条库里 3 条归档，一次都没进过包）。全量组包顺手把这层过滤
  去掉了，归档标记本身跟着条目一起同步。同时把"本地为空就不上传"的判定从 `CountEntries`
  （不含归档）换成 `CountAllEntries`，否则"全都归档了"会被误判成空库。
- 改：**自动同步间隔默认 30 → 120 分钟**，上限一天（1440），0 仍然是"只在手动点击时同步"。
  包是全量的，密到半小时只是白烧服务器配额。既有安装的 `settings.json` 里已存的旧值不会被
  偷偷改掉，要放宽请在设置页里自己调。
- 修：**图文混排的条目粘贴时只有文字过去（图丢了，还漏出一串令牌）**。以前回填正文型条目只写
  CF_UNICODETEXT，正文里的 `![](memoimg:ab12…)` 就原样交给目标程序 —— 图没了、聊天框里还多一串
  垃圾。现在**一次性写三种格式**：CF_HTML（图片内联成 data URI，浏览器/Electron 走这条）、
  RTF（图片嵌成 `\pict`，Word/WPS/Outlook/WordPad 走这条）、CF_UNICODETEXT（剥掉令牌的纯文本兜底）。
  HTML 由前端用**卡片同一套渲染器（marked）**产出后传给 Go，Go 负责把令牌换成真字节 ——
  不在 Go 里再养一套 Markdown 渲染器。
  顺带两件相关的事：① 程序化写 HTML/RTF 时开一个 1.2 秒的"回声窗口"，否则采集侧读回来算的是
  htmlHash/rtfHash、跟条目口径对不上，**复制一次就会多一条采集记录**；② 附件已被清理的图片整条
  丢掉，不会在目标里显示破图。
- 修（外观）：**卡片上"展开全文"的箭头**原来是文本字形 `⌄` / `⌃`（来自回退字体，12px 下
  又小又偏下，看着像不小心掉了个字符，两个状态的字形度量还不一样、按钮高度会跳）。现在统一用
  `IconChevron` 描边图标（与界面其它图标同一套 1.8 描边），展开时 `rotate(180deg)` 转上来，
  高度不随字形变。
- 修（外观）：同样的问题顺手清了三处 —— **待办页「展开已完成（N）」原来一个箭头都没有**
  （纯文字，看不出能点），补上同一个雪佛龙；**日历翻月的 `‹ ›`** 是同一类"文本字形当图标"
  （细一档、大小不齐），换成同一个图标转 90°。
  审计结论：全应用只有 `EntryCard` 用了字形箭头，其余折叠控件是"没有箭头"；`←`（返回）与
  `↑↓ 选择`（键位说明）保留原样 —— 前者是正规箭头字形、度量正常，后者是正文里的键位说明。
- 补：新增 11 条同步回归用例 + 8 条隐私模式分段用例（`scratch/privacy-mask-check.mjs`）。

## 2.9.3（2026-11-23）

这一版全在"两台机器怎么都同步不上 / 删了又回来"上。**第一条是要命的**：

- 修（数据层）：**老库的删除从来不产生墓碑**。`tombstones` 表还是旧主键 `(hash)`，
  而写墓碑用的是 `ON CONFLICT(hash, scope)`，SQLite 会整条拒绝
  （"ON CONFLICT clause does not match any PRIMARY KEY"），当时的代码又把这个错误丢了
  （`_, _ = db.Exec`）—— 于是**删除在本机成功、对端毫不知情**：对端旧包里的同一份内容
  会被当"新增"传回来。真机复现：11-23 在界面上删了 17 条，`tombstones` 一条没多，远端
  包里的 `deleted` 也没变。现在启动时 `Open` 会把这张表重建成 `PRIMARY KEY (hash, scope)`，
  老的 `scope='item'` 归到 `entry`（这台机器因此有 22 条老墓碑从"不可见"变回"可见"，
  在真库副本上验过：删除后墓碑数 +1、表定义已更新），并且**写墓碑失败就让删除整个回滚**，
  不再"删掉了但没留痕"。
- 修：**设备表/"测试连接"看不到对方包的大小与最后更新时间**。PROPFIND 只请求
  `<resourcetype/>`，坚果云（以及不少服务器）就只回 resourcetype，于是永远显示
  `0 B` / `—`。现在请求 `getcontentlength` / `getlastmodified` / `getetag`
  （在真实账号上验过：`11367 B · 2026-11-23 10:18`）。
- 修：**一个坏对端包会毒死整轮同步**。以前 `merge` 遇到解析失败的包直接 return，那一轮
  既不合并其他设备、也不上传自己的包 —— 一台坏包 = 这台机器永远不同步。现在跳过它、
  记账，「结果行」里明说"N 个对端包读取失败已跳过"，其余照常合并与上传。
- 修：**失败后只等下一个间隔**。开机 5 秒那一枪撞上网络没通（日志里就有
  `Mkcol … EOF`）就要白等 30 分钟。现在 1 → 3 → 10 分钟退避重试，成功后回到正常节奏；
  另外"刚同步过 60 秒内"不再跑第一枪。
- 修：`mkcol` 遇 HTTP 409 会无限递归（上级目录是 `.` 时"建上级"直接返回成功、
  再建自己又 409）。
- 修：每次保存设置都重启同步循环。设置页是自动保存的，改几个字段就连跑好几轮同步。
- 新增：**"隔壁目录体检"**。远端只有本机一个包时，顺手看一眼同账号、同级的其他目录里
  有没有另一个 `clipnest_data`；有就直接说"另一台机器的服务器地址很可能填成了
  `…/我的坚果云`"——这是"两台各写各的"最直接的解释。
- 新增：同步目录里认不出的文件、附件在本机已丢失、附件超预算没上传，都会出现在结果行里，
  不再是一句 `sync ok` 把线索全藏起来。
- 修：设置页「云同步」从来没人渲染 `panel.message`（列目录失败、目录里有认不出的文件、
  只有本机一个包的具体原因，全被吞掉了）。
- 修：**侧栏筛选器后面的数字和实际条数对不上**。两处原因：
  ① 角标（`EntryStats`）自己手写了一套 SQL，「剪贴板」按 capabilities
  （`actions LIKE '%,clipboard,%'`，"出现在快速粘贴列表"）数，而「我写的」按来源数 ——
  两个入口不互补，老数据 `actions` 为空的行两边一起漏、手写却带该能力的行又被算进去；
  真机实测「我写的 3 + 剪贴板 2」凑不出「全部 6」。现在角标**直接复用内置筛选器的查询**
  （同一个 `where()` 编译器），数字与列表不可能再漂；「剪贴板」改按**来源**（`source`）划分。
  ② 新建/编辑/置顶/归档/勾待办**都不发事件**，而角标只在收到 `clip:*` 事件时才重取 ⇒
  改完半天不动。现在这些写路径都会发 `clip:updated` + `clip:stats`。
- 修：`actions` 丢了「出现在快速粘贴列表」能力的老条目（真机上 3 条）在快速粘贴窗里
  根本不出现 —— 启动时一次性回填（幂等，日志里记一行）。
- 新增：**输入框里打 `#` 弹出已有标签**（自动补全/联想）。候选来自
  `GetEntryTags()`（按使用次数排序，15 秒缓存），支持前缀与包含匹配、大小写不敏感，
  `↑↓` 选择、`Enter`/`Tab` 插入、`Esc` 关闭、鼠标点选；插入的是 `#标签 `，走
  `Vditor.insertValue` 这条模型入口（不是直接改 DOM），所以正文与标签列立刻一致。
  三个写字的地方（详情 / 记一条 / 热键记一笔）共用同一层 `MarkdownSurface`，一处实现三处生效。
  - **中文输入法**：组词期间（`isComposing` / keyCode 229）一律放行，不拦 Enter/Space/方向键，
    否则候选没法确认；组词结束（`compositionend`）后立刻按已上屏的文字联想。
  - 鼠标点回一个**已经写好的** `#标签` 后面也会弹（`selectionchange` 以前先判断"弹窗已开"就返回，
    等于把这条常见路径整个关掉了）。
  - 点候选时先把焦点要回编辑器，再删令牌、`insertValue` 插入，并**手工同步一次外层 onChange**
    —— `insertValue` 不派发原生 `input` 事件，漏了这一步界面显示对了、库里草稿却是空的。
  - 插入后**光标落在标签后面**（Vditor 会在插入后异步重排、把原生选区重置回旧位置，
    所以要隔几个时间点再落一次；用户一动键盘/鼠标就立即停手，不跟人抢光标）。
  - **标签在编辑器里有独特样式**：用 Chromium 的 CSS Highlight API（`CSS.highlights` +
    `::highlight(clipnest-tag)`）给 `#标签` 上底色 + 强调色文字。只注册文本范围、不插 DOM，
    所以不会打断 contenteditable 的光标与 IR 结构（往正文包 `<span>` 是另一条会翻车的路）。
  - 外观：面板用 `--surface-3` + `--border-strong` + `--shadow-pop`（第一版误用了不存在的
    `--surface-1`/`--line`，整条 background/border 声明失效 ⇒ 弹窗透明、与背后界面糊在一起）。
  - 排查开关：`localStorage["clipnest.debugTagSuggest"]="1"` 会把选区/候选数写进 `clipnest.log`。
- 修：**日历热度点不跟着内容变**。`Calendar` 只依赖 `[month, query]`，采集/保存/删除
  之后那个点不会动（侧栏角标、列表、待办都刷了，只有日历停在打开那一刻）。现在跟随
  `liveSignal` 重算。
- 修：「今天 / 昨天」是渲染时算的相对日期，应用一直开着跨过零点不会改口。加了一分钟一次的
  时钟 tick（只有分组的标题重算，卡片上的 `HH:MM` 是绝对时间，不受影响）；快速粘贴窗里
  的「刚刚 / N 分钟前」同理，也接上了这个 tick。

## 2.9.2（2026-11-20）

- 改：设置 →「记一笔」弹窗透明 从四个按钮（关 / 15% / 30% / 50%）换成**滑块**，范围
  **0–100%**，每 5% 一档，右边实时显示当前值（0 显示"关"）。
- 说明：**100% = 卡片自己不再画任何底色**，露出来的是窗口背后的 DWM Acrylic 层，不是背后窗口的
  原样像素。实测：白底上卡片量到 `146,146,146`（Acrylic 的灰雾），彩色底上接近原样
  （蓝底 `21,102,208`，背后 `27,101,197`）。想要"文字直接浮在桌面上"这一档做不到 ——
  WebView2 那层表面不透明，页面 alpha=0 的位置只能露出 Acrylic。
- 实测（`scratch/e2e-capture-transparency.ps1 -Mid 100`）：0% `14,16,21` → 30% `54,55,59` →
  100% `146,146,146`（白底），三档都按像素验过。

## 2.9.1（2026-11-20）

- 修：**「记一笔」和快速粘贴窗不跟随主题切换** —— 两个弹窗都在应用启动时读一次
  `localStorage` 里记的配色，之后就再也不看了。所以应用跑着的时候在设置页换主题（或换深浅），
  主窗口当场变色，两个弹窗却要重启才跟上。现在它们和主窗口共用同一套
  `applySettingsTheme`（预设 / 深浅 / 自定义 CSS / 原生窗口边框），并订阅 `settings:changed`。
- 说明：**「弹窗透明」在浅色主题下看着像没生效** —— 其实生效了，是白叠白。实测
  （`scratch/e2e-capture-transparency.ps1`，按像素量）：浅色 + 蓝色背景，卡片
  `250,249,245 → 214,227,244`（明显带上背后的蓝）；浅色 + 白色背景，`250,249,245 → 243,242,240`
  （7 级差距，肉眼看不出）。深色 + 白色背景是 `14,16,21 → 54,55,59`。设置页的说明里写了这一点。

## 2.9.0（2026-11-20）
