# Gate 3 评估：哪些界面该走原生（MyGo `ui`），哪些继续用 WebView

> 2026-11-25 · 基于 2.12.1（宿主已换 MyGo，运行时零 Wails）
> 结论先给：**只有两块值得原生化——截图遮罩、快速粘贴窗。**
> 主窗、设置页、记一笔**不建议**动，理由在第五节。

## 一、先看清家底

| 项 | 数字 |
| --- | --- |
| 前端代码 | 9,077 行 ts/tsx + 3,314 行 CSS |
| 最重的三块 | `MarkdownSurface.tsx`（717 行，Vditor 编辑器）、`EntryDetailView.tsx`（447）、`Picker.tsx`（400） |
| 常驻内存（2.12.1，闲置销毁已开） | 主窗 52MB，三个弹窗都开过之后 120–180MB |
| 快速粘贴窗 | 单独进程 48–52MB；热键 → 可见 10.2ms（热）/ 29–36ms（冷建窗） |
| 截图遮罩 | 热键 → 可见 118–138ms（换壳前 Wails 版 183ms） |

MyGo 的 `ui` 包不是"只能画图"的低层库，它有 175 个导出函数，覆盖：
`TextInput`/`TextInputBuffer`/`TextArea`/`SearchField`/`TokenField`/`Autocomplete`、
`List`/`GridView`/`Table`/`Tree`（虚拟化 + `ListState`）、`Calendar`/`DateInput`/`TimeInput`、
`Select`/`Combobox`/`Segmented`/`Tabs`/`Sidebar`、`Dialog`/`Modal`/`Popover`/`Tooltip`/`Toast`、
`Scroll`/`ScrollBoth`、`Image`/`Bitmap`/`Icon`/`SVG`、`Video`、动画（`Keyframe`/`Tween`/`Spring`）、
主题（`LightTheme`/`DarkTheme`/`Themed`）、`Tester`（原生 UI 也能自动化测），
以及关键的 **`WebView`/`NativeWebView`——原生窗口里可以嵌一块网页**。

最后这个能力让"混合迁移"变成可能：原生窗口 + 内嵌 webview 各管一块，不必整窗全有或全无
（Wails 时代做不到，这是换壳带来的新自由度）。

**IME（中文输入法）**：`ui` 有组合串支持（`platform.TextComposition` 事件、`Element.Composing()`、
`ui/ime_undo_test.go`、`ui/compose_keys_test.go`、`ui/richtext/ime.go`）。所以原生输入框
原则上能打中文——但**我们没在 Windows 上实测过 CJK IME**，这条是决定 picker 能不能原生化的
唯一硬门槛，见第四节。

## 二、判定标准（先定尺子再看图）

一块界面适合原生化，要同时满足：

1. **不需要富文本编辑**（Vditor 那种"所见即所得 + 源码模式 + 粘贴 HTML"没有原生等价物）；
2. **交互简单**：画图 / 列表 / 单选 / 开关，而不是拖拽排序、多选合并、复杂表单；
3. **高频或延迟敏感**（否则原生化只换来"少一个 webview 进程"）；
4. **视觉可用少数绘制原语复刻**（矩形、线、图、文字），不需要 CSS 那套层叠/滤镜/阴影；
5. **不承担"信息密度"**：一屏里塞 30 个按钮、10 种字号的地方留在 web 更省事。

## 三、逐个界面的结论

| 界面 | 现状 | 原生可行性 | 建议 | 理由 |
| --- | --- | --- | --- | --- |
| **截图遮罩** `Shot.tsx`（173 行 + `shot.css` 108 行） | canvas 画冻结帧 + 蒙版 + 选框 + 尺寸标签 | ★★★★★ | **做**（Gate 3.1） | 全自绘、零文字输入、零滚动；Gate 1 已经用 MyGo `ui` 手搓过一版原型并跑通（拖框 → 裁切尺寸 1:1）。省掉一个 webview 进程与页面冷启，热键到可见还能再快 20–30ms，且**没有 WebView2 也不再影响截图** |
| **快速粘贴窗** `Picker.tsx`（400 行 + `picker.css` 321 行） | 搜索输入框 + 条目/片段混合列表 + 键盘上下选 + 回车直粘 | ★★★★☆ | **做，但必须先验 IME**（Gate 3.3） | 最热路径，单进程 48MB、冷建窗 29–36ms。`ui.List` + `SearchField` 天然对口；阻塞点只有"中文输入法在原生输入框里能否正常组合/候选/上屏"。搜索框若要保命，可先做"列表原生 + 输入框用 `ui.WebView` 开一个 40px 高的小 webview"这种畸形但稳的过渡 |
| **记一笔** `Capture.tsx`（169 行） | Vditor（`preset=capture`，工具栏隐藏）+ 拖拽拉伸 | ★★★☆☆ | **看你要不要真透明**（见第七节的实测） | 它用的仍是 Vditor：IR 所见即所得、粘贴富文本转 markdown。改原生会退化成纯文本编辑，但**只有这样才有「真半透明、不磨砂」**——像素已经量过 |
| **主窗**（`App.tsx` 446 行 + 各 view 共 ~2000 行） | 侧栏 / 时间线 / 日历 / 条目流 / 详情编辑器（Vditor）/ 对话框 | ★☆☆☆☆ | **不做全量**；可选"外壳原生化" | 4,000+ 行组件 + 2,300 行 CSS 的视觉细节，Vditor 无替代。真要做只能走 `ui.WebView` 混嵌：原生侧栏/标题栏 + 中间一块 webview（收益：看起来更"原生"，实测内存不变） |
| **设置页**（8 个 section，421 行 CSS） | 大量表单、滑块、热键录入、实时主题预览 | ★★☆☆☆ | **不做** | 表单密度高、改动频繁，且用户一两个月才进一次——原生化纯粹的搬砖 |
| **Toast / Tooltip / 右键菜单 / Dialog** | web 实现，和主窗同一套 token | ★★★☆☆ | **不做** | `ui` 都有对应控件，但它们在主窗里"长在页面上"（要跟着滚动、跟着元素定位）。单独原生化会立刻出现两套视觉语言 |

## 四、动手前必须先跑的三个原型（Gate 3.0）

任何一个不通过，就停在当前状态继续用 web——这不是坏事，2.12.1 已经能跑。

1. **中文输入法原型**（决定 picker 命运）
   一个 MyGo 原生窗口 + `ui.SearchField`，在 Windows 11 微软拼音下验证：组合串显示、候选窗位置、
   上屏、退格、Esc 取消组合、以及"边打边过滤列表"。**这是唯一可能一票否决的项。**
2. **列表手感原型**：`ui.List` + 1000 条混合行（条目/片段），量滚动帧率与首帧；
   对照现在 web 版的 `useEntries` 虚拟化。
3. **混嵌与主题原型**：一个原生窗口里 `ui.WebView` 嵌现有页面，验证
   `--app-region` 拖动、圆角/透明、以及**主题 token 的单一来源**（把 `themes.ts` 的
   CSS 变量喂给 Go 侧结构体，两边都从一份 JSON 读）。

顺带把**字体**验一遍：原生侧 CJK 走 `ui.RegisterFont` + `FontFamilies`，14px 小字的中文
在 native 路径上的 hinting 和 WebView2 不一致是常见塌方点。

## 五、收益的真相（别自欺）

- **内存**：闲置销毁已经把 753MB 打到 120–180MB。把 picker + shot 原生化，边际收益大约
  再省 **40–90MB**——是锦上添花，不是雪中送炭。
- **延迟**：真正的价值在"弹窗冷建"。原生 picker 可以把 29–36ms 压到 5–10ms；
  截图遮罩可以把 118–138ms 压到 ~90ms。**这是手感，不是数字游戏。**
- **战略**：热路径不依赖 WebView2，首帧不再可能白屏，也不再受 WebView2 版本差异影响。
- **成本**：每个原生化界面都要重新实现视觉与交互，并新增一套"原生侧 UI 测试"
  （`ui.Tester` 可用，但和 Playwright 式的前端测试不通用）。

所以：**先做截图（低风险高确定性），再验 IME，通过才碰 picker；其余保持 web。**

## 六、顺序与验收口径

| 阶段 | 内容 | 验收 |
| --- | --- | --- |
| Gate 3.0 | 上面三个原型 | 中文能打；1000 行滚动不掉帧；混嵌窗口的拖动/圆角/主题与 web 版一致 |
| Gate 3.1 | 截图遮罩原生化 | `scratch/e2e-shot.ps1` 全套通过（尺寸 1:1、Esc 不新增、剪贴板有图）+ 热键→可见 ≤100ms + 进程数 −1 |
| Gate 3.2 | 主题 token 单一来源 | 同一份 JSON 生成 `themes.ts` 与 Go 结构体；改一处两边都变 |
| Gate 3.3 | picker 原生化（仅当 3.0 的 IME 通过） | `scratch/e2e-picker-single.ps1` 通过（贴插入符 + 回车直粘 + 单实例）+ 冷建窗 ≤10ms + 内存 ≤15MB |
| 不做 | 主窗 / 设置 / 记一笔 / 通用弹层 | — |

## 七、实测补充：原生窗口的「真透明」成立（2026-11-25）

WebView2 上做不到「透明但不磨砂」（见 CHANGELOG 2.12.2 与 HISTORY 里记的两条死路）。原生窗口可以，用像素量的：

| 采样点 | 实测 | 理论 |
| --- | --- | --- |
| 卡片内部（`ui.RGBA(20,22,28,0.72)` 铺在白色窗口上） | **(85,87,91)** | 0.72×(20,22,28)+0.28×255 = **(85.8,87.2,91.6)** |
| 窗口四角（根元素还在填底色时） | (11,11,11) | `Column().Fill()` 画了主题底 → 去掉填充即为透明 |

也就是说：**原生窗口的 per-pixel alpha 会真的与桌面合成，中间不经过任何模糊层**。探针在
`scratch/mygo-native-popup/`（`go run ./scratch/mygo-native-popup`，9 秒自动退出）。

顺带两个观察：

- 原生窗口会建 `MSCTFIME UI` / `Default IME` 上下文窗口 —— IME 通路是接上的（但中文输入法仍要人手验，
  这是 picker / 记一笔原生化的共同前提）。
- 口径因此变成：**要「真透明」⇒ 这个弹窗必须原生**；只要能写 markdown ⇒ 留在 web。

### 把「记一笔」原生化要付的账

| 现在（web） | 改原生后 |
| --- | --- |
| Vditor IR：粗体就是粗体、粘贴富文本转 markdown、`#tag` 联想 | 纯文本编辑（markdown 退化成「源码」），富文本保真要自己接剪贴板 HTML |
| 主题走 CSS 变量（`themes.ts`） | 要在 Go 侧重建一套 token（建议与 `themes.ts` 同源生成） |
| 拖动 / 拉伸 / 尺寸记忆由浏览器 + `--app-region` 提供 | 原生自己实现（`ui` 有拖动区与 `OnResize`，我们已有经验） |
| 视觉照抄现有 CSS | 要重画，并新增一套原生 UI 测试（`ui.Tester`） |
| 弹窗进程 ~40MB、冷建窗 29–36ms | 进程 ~8MB、冷建窗 ~5ms |

**建议**：先做一天以内的 spike —— 原生壳（半透明圆角卡片 + 拖动 + 拉伸 + 按钮）+ 原生 `TextArea`
编辑区 + `#` 联想，跑 `scratch/e2e-capture-resize.ps1` 那套（尺寸记忆、最小尺寸、双击不最大化）
外加中文输入法验收。通过就替换；不通过就退回现在这块实心 web 卡片。
