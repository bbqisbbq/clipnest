# 评估：片段触发引擎该不该照 AutoIt / AutoHotkey 那一族来做

> **状态：评估结论已分批落地**（P0 的 `EndChars` 终止符、按应用的启用/排除、大小写敏感等）。
> 现行行为见 [../SNIPPETS.md](../SNIPPETS.md) 与 `internal/expand/`；本文只保留当时的对照与取舍。

> 现状基线：ClipNest 0.9.0。本文只做评估，**不含实现**。
> 参照对象：AutoIt 系自写热字串脚本、AutoHotkey v2 的 hotstring（`:*:` `:?:` `:O:` `:C:` `:R:` `:T:` `:B0:` `#Hotstring EndChars` 等选项）、以及 eTool 的短语触发。

## 一句话结论

**大方向已经对了**（全局钩子 + Unicode 注入 + 不碰剪贴板 + 输入法组词跳过），
真正缺的是三样「工程细节」，也就是那一族实现比我们成熟的地方：

1. **触发边界**：我们只认"固定后缀字符"，它认"任意终止符集合 / 词边界"
2. **注入通道回退链**：我们只有 SendInput Unicode → 剪贴板两级，它有 SendInput / WM_CHAR / SendPlay / 逐字符延迟四级
3. **逐条片段的触发选项**：大小写、是否保留缩写、在哪些程序里生效

按价值/成本排下来，我建议只做 **P0 三项**（约半天到一天），P1 选做，P2 明确不做。

## 二、逐项对照

| 维度 | 现在的 ClipNest | AutoIt / AHK 那一族 | 差距评估 |
| --- | --- | --- | --- |
| 触发边界 | 固定一个后缀字符（默认 `-`）；缩写写成 `addr` 时敲完 `addr-` 才触发 | `EndChars` 集合（默认 `` -()[]{}:;'"/\,.?!`` + Tab/Enter/Space），**任意**终止符都能收尾；`:*:` 可无终止符即时触发；`:O:` 连终止符一起吞掉 | **实质差距**。用户得记住"必须打 -"，而是人本能会打空格/回车 |
| 触发位置 | 缓冲区**末尾**匹配，2 秒 / 换窗口 / 空格 清空 | 词边界（`:` 前缀）、可限制只在行首、可用 `#IfWinActive` 限定程序 | 我们已解决"前面打了别的字"的问题，够用；缺"只在某程序里生效" |
| 大小写 | 一律不敏感 | `:C:` 敏感 / 默认不敏感 | 小差距，少见需求 |
| 删除已输入 | 一次性 `SendInput` 批量退格 | `:B0` 可完全不删（相当于"追加"）、`:R:` 原样发送 | 小差距 |
| 注入通道 | SendInput Unicode →（失败）剪贴板粘贴 | `SendText`(SendInput Unicode) / `ControlSendText`(WM_CHAR 直发控件，**不需要焦点**) / `SendEvent`(带延迟逐事件) / `SendPlay`(独立桌面，游戏兼容) | **实质差距**：我们遇到"某些输入框不接收注入"只能掉到剪贴板；它有中间档 |
| 逐字符节奏 | 64 字符一批，批间 2ms | 可设 `SetKeyDelay` / 每秒字符数 | 小差距；少数程序对速度敏感 |
| 输入法 | 组词检测即跳过 + 绝不改 IME 状态 | 默认不感知，常见做法是提示用户切英文 | **我们更强**，保持 |
| 撤销 | 无 | 有（第三方工具才有内建"撤销上次替换"） | 体验加分项，非必需 |
| 富文本片段 | 文本 / 图片 / 网址 / 文件 / 命令 / 程序 | 文本 + HTML（走剪贴板） | 小差距：加 HTML 片段成本很低 |
| 多字段模板 | `{{date}}` `{{clipboard}}` `{{cursor}}` | 变量 + `InputBox` 现场填参（`{Enter}`、`%clipboard%`、自定义对话框） | 中等差距；"填参对话框"是它们最好用的功能之一 |
| 触发建议 UI | 无（要么触发、要么不触发） | 有第三方脚本做"候选列表" | eTool 有；体验强，但成本高 |
| 数据模型 | SQLite + 分组 + 使用次数 + 哈希合并 + 云同步 | 脚本/纯文本文件，无同步概念 | **我们明显更强** |

## 三、P0（建议做，约 0.5–1 天）

### P0-1 触发边界改成「终止符集合」，保留后缀模式

- 默认终止符：`空格` `回车` `Tab` `,` `.` `;` `:` `!` `?` `)` `]` 以及原有后缀字符
- 语义：缓冲区末尾出现任一终止符时，尝试匹配**它前面**的最长触发器
- 保留「固定后缀模式」作为可选（现有用户的肌肉记忆不会坏）
- 顺带支持「敲缩写后就触发」（无终止符）→ 需要前缀唯一性判断，容易误触发，**默认关闭**
- 影响面：只动缩写匹配（现为 `internal/expand/` + `snippet_host.go`）与设置项 `expandEndChars`

### P0-2 注入通道回退链 + 按应用覆盖

```
SendInput(Unicode)  →  WM_CHAR(焦点控件，直接投递)  →  剪贴板 + Ctrl+V
```

- 每级失败自动降级，日志写明用了哪一级（现在只有两级且不记录成功级别）
- 设置里给「按程序指定通道」（进程名 → 通道），解决"微信/某些 Electron 框里替换不生效"
- 影响面：`picker_windows.go` 注入层 + 设置页

### P0-3 逐条片段的触发选项（最小集）

| 选项 | 作用 |
| --- | --- |
| 大小写敏感 | 区分 `Addr-` / `addr-` |
| 触发后保留缩写 | 相当于 `:B0`，在缩写后面追加内容 |
| 仅在这些程序生效 / 在这些程序禁用 | 进程名列表，避免在 IDE/终端里误触发 |

## 四、P1（选做，各半天左右）

- **富文本（HTML）片段**：复用已有 `WriteHTMLToClipboard` + 剪贴板通道，Word/邮件里保留格式
- **填参变量**：`{{ask:标题}}` 触发时弹一个小输入框，值填进文本（对应它们的 `InputBox`）
- **撤销上次替换**：托盘菜单/快捷键，把光标处内容换回缩写（需要记住上一次替换的位置与原文，跨程序不保证）

## 五、P2（明确不做，或先不做）

- **正则触发器**：误触发率与调试成本高，用户需要学一遍正则，收益低
- **`SendPlay` / 独立桌面注入**：要给游戏用，得处理反作弊误判，风险 > 收益
- **每条片段注册独立热键**：几千条片段会让 `RegisterHotKey` 或钩子分发表爆炸；单钩子 + 内存表已经够快（每次按键 ≤32 次 map 查找）
- **中文模式下"拼音串当触发器"**：能做，但会与输入法候选词抢按键，坏的体验比好的体验多

## 六、如果按上面的做，最终形态

```
你打 "addr" 然后按空格
   ↓ 钩子：缓冲区末尾是空格（终止符）
   ↓ 内存表：最长匹配触发器 = "addr"（片段：办公地址 · 文本）
   ↓ 吞掉这次空格 + 批量退格 4 个字符
   ↓ 注入通道：SendInput Unicode（该程序被标记过就换 WM_CHAR / 剪贴板）
   ↓ 类型化 "杭州市滨江区 · ETool 科技园 A 座 1208"
   ↓ {{cursor}} 存在就再补 ←
```

对照现状，唯一的区别是**第 1 步**：不再要求你打 `-`。剩下都是可选的精细度。
