# ClipNest 2.8.1

> 2.8.0 的构建在发布十分钟后被真机 e2e 抓到一处硬伤：**输入框里敲的字没有实时同步给应用**
> （Vditor 的 `options.input` 在 IR 模式手打时不触发），于是「草稿」这一条等于没生效。
> 2.8.1 修的就是这个，功能清单与 2.8.0 计划的一致。请在 2.8.1 上验收下面这些。

## 2.8.1 相比 2.8.0 的改动

- **内容的 onChange 改听编辑器宿主的 DOM input 事件**（外加失焦补一次），不再依赖 Vditor 的
  `options.input` —— 它只在 Vditor 自己走 `setValue`/渲染流程时回调，手打文字不触发。
  连带修好了详情页「未保存」标记的同一个隐患。
- 端到端验收脚本：`scratch/e2e-global-composer.ps1`（沙箱 APPDATA + 真实鼠标）：打字 → 草稿进库 →
  切待办/设置内容不变 → 杀进程重启内容还在 → 设置页点开关立即落盘。

---

这一版全是"用着别扭"的地方：输入框到处消失、写了一半的字切页就丢、设置要手点保存、日历右侧被切掉。

## 底部「记一条」现在是全局的

以前这块输入框挂在内容视图里面，于是**切到待办或设置，它就没了**；更糟的是它的草稿是那个视图的
本地状态，视图一卸载（去设置再回来、打开详情再回来）就清空——写了一半的东西不算保存，但也不该凭空消失。

现在它是窗口的一部分：

- **每一屏都在同一个位置**：换筛选器、去待办、进设置，输入框都还在，内容也不动；
- **草稿跟着库走**：停手 0.4 秒写进 `clipnest.db`，**关掉应用再打开，写了一半的内容还在输入框里**；
  存成条目之后自动清空，不会重启又被塞回来；
- 只有打开某条条目详情时不显示（那是在改已有的内容，不要两个"保存"抢地方）。

## 导航：默认筛选器 + 关设置回原处

- 任一筛选器行的 `⋯` 菜单里可以**设为默认打开**，行尾会显示一个「默认」小标；下次启动直接落到它。
  （这项只在本机生效：筛选器本身不跨机器同步，指过去也是一个不存在的 id。）
- 进设置页之后，点左上角 **← 返回**、或再点一次侧栏「设置」，**回到进来之前那一屏**——
  筛选器、选中的日期原样都在。

## 设置改一下就保存

没有「保存 / 撤销」按钮了：停手 0.4 秒自动落盘，顶部一行状态写着「已自动保存 14:32」。
切开关、拖滑块、改快捷键都不用再想"我存了没"。保存失败会把改动留着并提示，下次编辑再试。

## 日历不再溢出

真 bug：侧栏日历右侧被切掉（15 / 22 / 29 看不见），整条侧栏还多出一条横向滚动条。
根因是 `<button>` 自带的左右内距让每个格子最小 27.6px，而 `repeat(7, 1fr)` 的最小宽度就是
min-content，七列加起来 217px、撑破了 193px 的卡片。改成 `repeat(7, minmax(0, 1fr))` 并清掉
按钮内距后，任何窗口尺寸下七列都恰好贴合。（测量脚本：`scratch/layout-preview/measure-cal.mjs`。）

## 内部整理

- `App.tsx` 里的筛选器增删改抽成 `hooks/useFilters.ts`，草稿抽成 `hooks/useComposerDraft.ts`，
  输入框拆成 `Composer`（长相）+ `ComposerDock`（行为）；
- 日期键统一到 `lib/dates.ts`（以前 `App.tsx` 与 `Calendar.tsx` 各写一遍）；
- 设置页底部保存条的样式与 `is-shown/is-dirty` 补丁一并删除，换成顶部状态条；
- 新增 3 条 Go 单测（草稿落库 / 空白清空 / 超长截断），`docs/ARCHITECTURE.md` 与
  `docs/design/2026-11-19-global-composer-and-nav.md` 同步更新。

## 安装

覆盖安装即可，设置与条目都保留。装完之后一次更新检查就能看到这个版本已经带签名。
