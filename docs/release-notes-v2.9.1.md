# ClipNest 2.9.1

> 修 2.9.0 的一个毛病：**两个弹窗不跟随主题切换**。外加把「弹窗透明」在浅色主题下
> 为什么看着像没生效说清楚。覆盖安装即可，设置与条目都保留。

## 一、弹窗现在真的跟着主题走

快速粘贴窗（Ctrl+Shift+V）和「记一笔」（Ctrl+Shift+N）都是随应用创建、**一直活着**的窗口。
它们各自只在启动时读一次"上次记住的配色"，之后就再也不看了 —— 于是在设置页换主题（或换深浅）时：

- 主窗口：当场变色 ✓
- 两个弹窗：还是要重启 ClipNest 才跟上 ✗

现在三个窗口共用同一套落地逻辑（配色预设 / 深浅 / 你的自定义 CSS / 原生窗口边框），
并且都订阅"设置已变"。换完主题直接按 Ctrl+Shift+N，浮窗就是新配色 —— 不用重启。

顺带一个隐性修复：原生窗口边框的深浅标志也一起更新了。它同时决定 DWM 那层 Acrylic 底色，
标志不更新时浅色主题会糊出一层深色。

## 二、「弹窗透明」在浅色主题下为什么看不出

因为这个开关是**真透明**（不是毛玻璃）：卡片底色按比例变透明，露出来的是**你背后的东西**。
浅色主题下，卡片本身是米白（`#faf9f5`），浅色模式的 Acrylic 也是接近白的，背后再压一份
白文档（Word / 网页）—— 白叠白，量出来只差 7 级，肉眼当然看不出。

实测（`scratch/e2e-capture-transparency.ps1`，按像素量，不看截图印象）：

| 主题 | 背后 | 0%（实心） | 30% | 差 |
| --- | --- | --- | --- | --- |
| 深色 | 白窗 | `14,16,21` | `54,55,59` | 40 级，一眼可见 |
| 浅色 | **蓝色**窗口 | `250,249,245` | `214,227,244` | 36 级，明显带上背后的蓝 |
| 浅色 | 白色窗口 | `250,249,245` | `243,242,240` | 7 级，看不出来 |

所以：**开关是工作的**。浅色主题下把「记一笔」浮在深色编辑器、图片、彩色网页上就能看出来；
浮在纯白文档上就是看不出。设置页的说明里现在写了这一句。

## 三、验证

- `scratch/check-theme-sync.ps1`：用托盘「暂停收集」触发一次真实保存，日志里能看到
  `[theme-sync] preset=… mode=picker` 与 `mode=capture` 两行 —— 两个弹窗确实收到了设置变更。
- `scratch/e2e-capture-transparency.ps1 -Preset default-light -Backdrop '#1e6fd9'`：
  上表三行数据都由它量出来（脚本现在也支持指定主题预设与背景色）。
- `go test ./internal/...`、`npx tsc --noEmit`、`npx vite build` 全绿。
