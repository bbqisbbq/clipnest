# ClipNest 2.10.0

一句话：**按一次快捷键，框哪截哪，截完自动进历史（还顺手在剪贴板里）。**
顺手修掉了一个很难解释的老问题：网页上复制图片，存下来的是**图片的链接**。

## 框选截图

`Ctrl+Shift+A`（设置 →「交互与启动」可改，留空即不注册）。

- 按下后**整屏先冻结，再开遮罩**：你看到的画面就是待会儿截到的东西，拖框时背后不会有窗口乱动。
- 拖一个框、松手，就存成一条**图片条目**，同时放进剪贴板——截完直接 `Ctrl+V` 就能用。
  不想让它动剪贴板，把「截图后复制到剪贴板」关掉即可。
- `Esc` 取消；只点一下不拖（小于 8px）也当取消，不会给你存一张 2×3 的图；右键同样取消。
- 只截**光标所在的那块显示器**：多屏时在哪个屏上按的快捷键，就截哪个屏。
- 截图条目照常进 OCR 队列——**图里的字也搜得到**。
- 托盘菜单加了「截图（框选）」：热键撞了别的软件时（或者你干脆没设），这里也有入口。

细节上做了两件"不显眼但会立刻被感知到"的事：

1. **遮罩按物理像素铺满显示器**。窗口位置/尺寸走 Win32 `SetWindowPos`，不经过 Wails 的 DIP
   换算——否则在 125%/150% 缩放的屏幕上遮罩会比屏幕小一圈，右边缘会漏一条桌面进去。
2. **截出来的尺寸与拖出来的完全一致**。裁切在前端按 `naturalWidth / clientWidth` 换算，
   不猜系统 DPI；真机验证：拖 768×432，条目就是 768×432。

## 网页「复制图片」不再存成链接

这个问题的真因值得写清楚：**浏览器的「复制图片」根本没往剪贴板放位图**。
在真机上用 `scratch/clipfmt` 抓格式清单，Chrome 里选中网页图片按 `Ctrl+C`，剪贴板里只有：

```
HTML Format  →  <img src="https://…" alt="…">
CF_UNICODETEXT → (alt 文字)
```

没有 `CF_DIB`、没有 `PNG`。所以老版本把它归成「富文本」，历史里就剩一条指向图片地址的记录——
看起来像"存了链接"，其实是**压根没有图可存**。

现在的做法：认得出"整段就是一个 `<img>`"的片段，就去把这张图下载回来，存成**图片条目**。

- 设置 →「采集」→「**网页图片自动下载**」（默认开）。关掉则只记一条带地址的富文本。
- 单张上限 24 MB、超时 8 秒、带浏览器 UA（不少站点防盗链）。
- 下载**在后台跑**，不占采集线程：下载再慢，也不会把你这期间复制的东西挤掉。
- 抓不到（断网、防盗链、WebP/AVIF 这类暂时解不了的格式）就**退回富文本条目**并记一行日志——
  这次复制不会凭空消失。

## 顺手修掉：热键"注册成功"可能是假的

Wails 的 `GlobalShortcut.Register` 在 `app.Run()` 之前只是**排队**，真正的 `RegisterHotKey`
在启动后才 flush，失败只经由错误处理器上报，调用方拿到的是 `nil`。
结果就是最难受的那种故障：设置页说"已保存"，按下去毫无反应，日志里也没有对应的一条。

现在注册前先用 Win32 试一次（注册即注销），"这套组合键已被别的程序占用"变成**当场可读的错误**。
顺带一个体贴：如果**默认**截图键在启动时就被占用，只记一行日志提醒，不会让你之后每次改设置
（哪怕只是换个主题）都被"截图快捷键注册失败"拦住；你换一个能用的键，一切照常。

> 实测这台机器上 `Ctrl+Shift+A` 已经被别的程序占了 —— 打开设置 →「交互与启动」，
> 点一下「截图快捷键」录一个新的组合键即可（`Ctrl+Shift+Z` 之类）。
