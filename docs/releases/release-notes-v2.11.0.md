# ClipNest 2.11.0

一句话：**复制一张图片文件，条目里就是那张图；点开详情什么都不改，返回也不会再问你要不要保存。**

## 复制图片文件：存的是图，不是路径

以前在资源管理器里 `Ctrl+C` 一张 `jpg`/`png`，历史里只落下一行 `D:\照片\DSC01234.jpg` ——
对用户没有任何意义，原文件一挪走就彻底废了。

现在：**恰好一个图片文件**（png / jpeg / gif，源文件 ≤ 24 MB）时，图本体直接存进库里：

- 卡片上显示的就是这张图，点开能看到大图，双击进详情正常编辑
- 图里的文字照常进 OCR —— 之后用图里的字就能搜到它
- 存的是**原始字节**，不重新编码：画质不掉、体积不涨；「复制」回剪贴板也照旧能用
- 文件路径仍然记着（详情页能查到来源），但不再是条目的全部内容

**仍然只记路径的情况**（有意为之）：一次复制多个文件、文件夹、`webp`/`avif`/`psd` 这类
ClipNest 解不开的格式、以及超过 24 MB 的文件。剪贴板管理器不是相册，
一次几百 MB 的归档会让库和同步包都难受。这些边界见 [FILE-STRATEGY](../FILE-STRATEGY.md)。

## 修：详情页什么都没改，返回却问「有没有未保存的修改」

这个 bug 解释起来有点绕，但值得说清楚，因为它属于"修一个动作，得先搞明白它为什么错"：

编辑器（Vditor 的即时渲染模式）**载入内容时会按自己的规范重排一次** —— 表格会补空格对齐、
`[X]` 会变成勾选框、行尾的空格会被吃掉。同时，编辑器**失焦时会把当前内容上报一次**
（这是为了兜住"敲完立刻点别处"的最后一次改动）。两件事叠在一起：

> 你点「返回」→ 编辑器失焦 → 上报一次内容 → 和库里的字节比对 → **判成"改过了"** → 弹窗问你要怎么处理。

修法是换基线：不再拿"库里的字节"当基准，而是让编辑器在就绪时回报**它自己的规范化值**当基线，
并且"值没变就不上报"。两边同源之后，只有真人的改动才算改动。

现在的行为：打开详情 → 右上角是「已保存」→ 按 `Esc` 直接回列表；
真敲一个字 → 立刻出现「未保存」徽章、按钮变可点。两种情况都有真机脚本钉着
（`scratch/e2e-detail-dirty.ps1`）。

## 验证过什么

- `go test ./internal/...`：新增 5 组用例（单张 png/jpeg/gif 存成图；多选 / 非图片 / 坏文件 /
  目录 / 超 24 MB 退回引用；`CF_HDROP → 条目 → 附件` 全链路的字节一致与 `image/jpeg` MIME）。
- **真剪贴板**投一张 jpg（真 `CF_HDROP`）：条目正文变成 `![](memoimg:…)`，卡片直接显示图片，
  OCR 识别出图里的字。
- **真键鼠** e2e：打开详情不改 → 不脏；`Esc` → 回列表、不弹窗；敲一个字 → 变脏。
- `npx tsc --noEmit`、`npx vite build`、`go vet ./internal/...`、`scripts/visual-check/check-css.ps1` 全绿。
