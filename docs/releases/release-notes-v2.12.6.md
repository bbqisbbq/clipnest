# ClipNest 2.12.6

## 「记一笔」再也不会丢草稿了

你在「记一笔」里打了一半的字，以前是**只活在那个窗口自己的内存里**的。

而这个窗口有个省内存的机制：你把它关掉（按 Esc 或点 ×）之后闲置 1.5 秒，它会被整个销毁 ——
下次按热键再建一个新的。窗口一销毁，里面打的东西就一个字节都不剩了。日志里
`idle: capture window destroyed` 一天几十条，等于**每次关窗都在丢一次稿**，而现象看起来
就是"我明明写了啊"。

现在它和主窗口底部那个「记一条」用同一套机制：每敲一个字就落进数据库。

- 按 Esc 关窗 → 重开，字还在
- 被闲置销毁 → 重开，字还在
- 退出应用、甚至任务管理器强杀 → 重开，字还在
- 存成条目之后草稿自动清干净，不会下次开窗又冒出来打扰你

重开时左下角会有一行小字提示 **「已恢复上次未保存的草稿」**，免得你以为这是自己上次保存过的内容。

## 一个细节：两份草稿分开存

主窗口底部的「记一条」和「记一笔」可以同时开着。它们的草稿是**两份**（数据库里两把键），
所以在一边打字不会把另一边正在写的东西覆盖掉。

## 怎么验的

不是"改完觉得对了"，是真机走了一遍完整链路：

1. 起应用 → 按热键弹出「记一笔」→ 打两行字 → 按 Esc
2. 等日志出现 `idle: capture window destroyed`（确认走的确实是"销毁"那条路，而不是窗口没关）
3. 再按热键：编辑器里两行字原样回来，左下角提示也在
4. 关掉进程直接读数据库：`capture.draft` 两行都在
5. 另起一轮打字 + Ctrl+Enter 存成条目 → 草稿被清空

回读编辑器内容不是靠看截图，是把内容拷出来逐字比对的（截图只当佐证）。

## 升级

装 `clipnest-2.12.6-amd64-setup.exe`（右键以管理员身份运行），数据与设置不受影响。
