# ClipNest 2.13.1

## 修两个语义搜索的问题

**一、装完一直显示「已索引 0 条」**

模型下载好了、状态显示「已就绪」，但索引数是 0，搜索也没变化。

原因挺低级：存向量的那一列是 `BLOB NOT NULL`，而写"排队中 / 失败 / 跳过"这几种
**还没有向量**的状态时，代码传了一个空切片 —— 在 Go 里这会被当成 NULL 绑进 SQLite，
被 NOT NULL 直接拒掉。于是整张表一行都没有。

现在已经改成空向量按空 BLOB 存。你**不用做任何操作**：更新到这个版本后，启动后
20 秒内它会自动把历史条目补编一遍（每条约 6 毫秒，界面上能看到「已索引 N 条」在涨）。

顺带把那次被吞掉的错误改成了必须冒出来 —— 这个 bug 之所以能活过一版，就是因为
写入失败的那次返回值被 `_ =` 忽略了。

**二、纯图片条目污染搜索结果**

截图类条目的正文只有一个图片令牌（`![](memoimg:xxx)`）。它们被编码成"一串哈希字符"
的向量，彼此高度相似、和任何查询都半像不像，于是**霸占结果头部**：实测一次搜索的
前五条里四条是这种空图。

现在这类条目会被跳过、不进检索。等 OCR 把图里的字认出来，它自然又会变成可搜索的 ——
比如你那张同步设置面板的截图，现在搜「同步不上去」它排第一。

## 升级

装 `clipnest-2.13.1-amd64-setup.exe`（右键以管理员身份运行）。模型资源不用重下，
数据与设置不受影响。
